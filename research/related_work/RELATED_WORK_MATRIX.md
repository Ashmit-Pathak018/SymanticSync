## Source-to-claim notes from the supplied paper collection

- **Synql:** `C:\Users\ASMIT\Downloads\DBMS-REVIEWPAPERS\Synql.pdf`, pp. 18–35 (PDF pages 1–18). Its abstract and introduction say the approach composes CRDT primitives and compensates user modifications; its stated aims include combined operation intent and integrity. This makes it a close prior system, not evidence that SemanticSync is novel. The paper itself identifies the DAIS 2024 proceedings and DOI `10.1007/978-3-031-62638-8_2`.
- **Riffle:** `C:\Users\ASMIT\Downloads\DBMS-REVIEWPAPERS\Riffle (2023).pdf`, abstract and §§1–3. It presents a local-first application architecture using client-side persistent relational state, reactive relational queries, and synchronous transactional updates. Its ACM reference block identifies UIST '23, Geoffrey Litt, Nicholas Schiefer, Johannes Schickling, Daniel Jackson, 16 pages, and DOI `10.1145/3586183.3606801`. This is adjacent local-first relational application work, not a direct semantic-conflict comparison.
- **CRDV:** `C:\Users\ASMIT\Downloads\DBMS-REVIEWPAPERS\Conflict-free Replicated Data Views (2025).pdf`, pp. 1–2 and 27. The source states SQL views define varied merge semantics/types over replicated relations; its ACM reference block reports PACM Management of Data 3(1), Article 25, February 2025, 27 pages, DOI `10.1145/3709675`. This directly narrows the possible contribution claim: SemanticSync cannot claim SQL-expressed merge logic as a unique idea from this comparison.
- **Replicated relations and updatable views:** `C:\Users\ASMIT\Downloads\DBMS-REVIEWPAPERS\Eventually-Consistent Replicated Relations and Updatable Views (2023).pdf`, abstract and §2. The authors describe a delta-state CRDT model and state convergence after replicas apply the same update set. This is a model-specific result and is not transferred to SemanticSync.
- **Merge What You Can, Fork What You Can't:** supplied PDF, abstract and §2. It preserves multiple event histories for conflicting edits and allows manual reconciliation. This is related to reviewable conflicts but has a different state model from SemanticSync's row-level conflict records.
- **ConLoc:** supplied PDF, abstract and introduction. The paper describes synthesized synchronization using an SMT solver to enforce invariants. It is a stronger, distinct formal approach; SemanticSync's enumerated FK paths and finite tests are not equivalent evidence.

These are paper-content checks, not a systematic literature review. Any statement about what a system does not support, or comparative performance, requires additional source and implementation evidence.

## Comparison rules

- Do not represent a system's unmentioned feature as unsupported.
- Compare only matching state models, operations, failure assumptions, and metrics.
- Record version and artifact commit for software comparisons.
- Report paper guarantees with their assumptions; do not transfer them to SemanticSync.
- Do not use this selective matrix to state that no prior work supports configurable semantic merge policies.
