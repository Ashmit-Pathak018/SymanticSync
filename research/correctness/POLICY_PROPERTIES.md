# Policy Semantics and Property Boundaries

The resolver implementation is in `backend/engine/semantic_resolver.py`; policy compatibility and bounded syntax are in `backend/engine/policy_registry.py` and `policy_validator.py`. Resolver properties and engine delivery properties are separate.

| Policy | Implemented resolver behavior | Property that can be stated mathematically | Evidence and remaining boundary |
|---|---|---|---|
| `SUM` | Computes `a + b - base`, substituting zero for `None`. | For a fixed shared base and exact arithmetic, adding two deltas is commutative and associative as a sum of deltas. | Generated resolver tests and selected engine tests cover bounded integer domains/common-base cases. Does not prove arbitrary sequential history, floating-point exactness, or arbitrary pairwise relay convergence. |
| `BOUNDED_SUM` | Adds tracked signed deltas; requires explicit finite inclusive bounds; unsafe candidates/observed values are flagged or remain pending, not clamped. | Candidate arithmetic is order-independent in exact arithmetic for a fixed base; a particular delivery prefix may still violate bounds. | Generated fixed-bound commutativity test plus boundary, identity, retry, restart, and N=3/5 finite-schedule tests. Tests do not establish arbitrary-order convergence. |
| `AVG` | Computes unweighted `(a + b) / 2.0`; no sample count/weight is retained. | Binary mean is commutative for finite real inputs; repeated binary averaging is not associative and does not equal a general multi-sample mean. | Concrete non-associativity regression. No sufficient-statistic representation for N-way mean. Floating-point and non-finite behavior needs policy-specific limits. |
| `APPEND` | Returns the changed side if the other equals base, returns identical current text once, otherwise concatenates full strings using replica-ID order and `; `. `None` becomes empty text. | Pairwise call is deterministic for fixed arguments/IDs; it is not a set-union operation over uniquely identified contributions. | Tests cover delimiters/Unicode/empty/None and selected repeat sync. General contribution deduplication, arbitrary merge order, and N-way idempotence are unverified and not guaranteed by this implementation. |
| `LWW` | If both timestamps exist, higher timestamp wins; timestamp ties use replica ID. If either is missing, replica ID decides. | The explicit comparison/tie-break is deterministic and totally ordered only within the implemented input rule. | Resolver and sync tests cover selected ties/order cases. Timestamp order is not proof of causality; deterministic selection may discard an independent update. |
| `REJECT` | Flags a conflict and returns `None`; resolution requires review. | Flagging is deterministic for a fixed conflicting input. | Selected tests verify persistent conflict/resolution behavior. No performance or human-intervention-time study. |
| `MIN` | Calls Python `min(a, b)`; policy validation is intended for INTEGER/REAL/NUMERIC declared columns. | For mutually comparable values, min is commutative, associative, and idempotent in the value algebra. | Tests cover supported numeric inputs. SQLite affinity, mixed storage classes, NULL, NaN, and arbitrary collation behavior are not generalized by the algebra statement. |
| `MAX` | Calls Python `max(a, b)`; policy validation is intended for INTEGER/REAL/NUMERIC declared columns. | For mutually comparable values, max is commutative, associative, and idempotent in the value algebra. | Same scope as MIN; no claim for arbitrary SQLite values or histories. |

The deterministic generated tests are finite executable checks. They are not formal proofs. In particular, tests of a resolver function do not prove operation identity, deduplication, replay safety, or convergence of the engine protocol.

## Explicit operation-based increment (not a resolver policy)

`CRDTSyncEngine.apply_increment` records `op_type=INCREMENT`, a signed numeric delta, and a stable operation ID separately from the absolute-value `apply_change`/`UPDATE` path. Tests verify that two independent contributions, including equal-valued contributions, are both applied; duplicate IDs are received once; two increment siblings can be delivered in reverse sequence order; a restarted engine can repeat sync without adding them again; and a concurrent absolute SET is rejected for review under `REJECT`. Tracked increments preserve integer precision within SQLite's signed 64-bit range and verify persisted trigger effects before logging. Checkpoint post-manifest tail recovery validates an INCREMENT's dependency and prior-value precondition before replay-checking it.

These are finite two-replica tests. They do not establish arbitrary three-or-more-replica schedules, concurrent processes, unbounded exact numeric arithmetic, general interaction with every policy, or a formal convergence result. The historical stress matrix remains SET-based and is unchanged.
